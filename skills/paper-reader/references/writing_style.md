# 写作风格：减少 AI 味

论文解读写作阶段（Step C3）的文风纪律，提炼自 `writing-rigor` skill 的意图。「源 vs 解读的区分」和「scope 守住」中英文都适用；标点和套话的具体反模式针对中文输出（英文给出等价处理）。

如果环境里装了 `writing-rigor` skill，它的 `references/ai-flavor-patterns.md` 和 `references/source-grounding-rules.md` 是更完整的版本，可一并参考。

一句话原则：写得像真懂这篇论文的人随手写下来的，不是像 AI 生成的。

## 1. 源 vs 解读：用散文区分，不用标签

论文明确说的，和我的展开 / 推测 / 类比，必须让读者分得清。但**不要**用 `[解读者注]` `[解读者展开]` `[解读者类比]` `[解读者推测]` 或 `**解读者注**：` 这类括号 / 粗体标签（英文的 `[Interpreter's note]` 同样不要）。这些标签视觉上像贴 sticker，把「区分」的责任从语言降级成模板，AI 味重。

替代做法：
- 紧跟论文 quote block 的散文段，默认承接论文内容。
- 我的解读另起一段，开头一句就让读者听出来：「论文没展开这个机制，可能的原因是…」「我的理解是…」「从 Figure X 看…」「这是我用来帮助理解的类比，不是论文的说法」。英文用 "The paper doesn't say why X; my reading is…" / "An analogy I find useful…"。
- 整段都是推测时，开头点明「下面是我读完后的疑问，都是推测，不是论文陈述」，然后直接写，不逐条贴标签。
- 同一段里既有论文事实又有我的推测：先用 quote block 隔开论文部分，再用框架句承接解读，不要用括号标签插在句中。

## 2. 标点癖（中文）

| 反模式 | 替换 |
|---|---|
| `——` 当万能分隔符 | 句号、冒号、「，比如」「，也就是」 |
| `→` 当连接词（「X → Y」代「X 导致 Y」） | 「所以」「于是」「得到」「，」 |
| 一段里 3-4 个 `→`，读起来像流程图 | 写成正常句子，或真的画图 |
| 标题分隔符 `：` 和 `——` 混用 | 统一用「：」 |

## 3. 模板化结构

| 反模式 | 替换 |
|---|---|
| 「招 1: …」「招 2: …」当子标题 | 用内容本身做标题（「自适应熵控制」而不是「招 1」） |
| 「V4 的四招」「三条规则」式列举预告 | 直接列，不预告数量 |
| 「下面从三个方面分析」 | 直接进入第一个方面 |
| 每段都 1. 2. 3. 数字 bullet | 该用列表才用，不该用就写成段落 |
| 「来龙去脉」「澄清：X 不是 Y」当小节标题 | 用具体的「为什么 X」/「X 的实际含义」 |

## 4. 套话和自夸

删掉或换成具体描述：
- 「关键」「关键 trick」「核心 insight」「核心是」「本质是」「本质上」直接删，直接说事，读者自己判断什么重要。
- 「一句话总结」后面跟一整段 → 真写一句话，或改「简短说」。
- 「优雅地」「漂亮地」「完美解决」修饰自家/论文方案 → 陈述事实，让读者评判。

## 5. 因果链 AI 模板

「X 一变，Y 也跟着变，Z 也跟着…」「X 一换 Y 就变」是 AI 连锁因果模板，机械感强。改成「不同 X 对应不同 Y」的并列陈述，去掉「触发」感。例：「shape 一变 kernel 一变，累加顺序也跟着变」→「不同 shape 选不同 kernel，对应不同的累加顺序」。

## 6. 粗体堆砌

一段最多 1-2 个粗体，用在真需要视觉锚点的地方（术语首次出现、跳读要抓住的词）。不要每段开头 `**关键是…**` `**核心 insight 是…**`，也不要一段堆 3-4 个 `**XXX**`。

## 7. 术语

用领域常用术语，别用模型从训练里组合出的「听起来专业」的生造词（如「数值表示」代「浮点」、「三档精度」乱比喻、「极小数值差异」代「差几个 ulp」）。论文里出现的术语优先沿用论文的写法。

## 8. 公式与渲染环境

解读文档中的数学表达必须保留为 LaTeX。统一的源码格式比针对某个查看器临时降级更重要，也能避免 ASCII 和 Unicode 近似写法造成歧义。

- 行内变量、运算和短公式使用 `$...$`，例如 `优势函数为 $A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s)$。`
- 独立公式、推导或较长表达式使用 `$$...$$`，例如：

  ```markdown
  $$
  V^\pi(s)=\mathbb{E}_{a\sim\pi(\cdot\mid s)}\left[Q^\pi(s,a)\right]
  $$
  ```

- 这条规则适用于正文、列表、表格、引用块、图注和后续问答写回的内容。数学含义的变量也用 LaTeX，例如 `$s_t$`、`$\gamma$`、`$p(a\mid s)$`。
- 禁止把公式写成行内代码、围栏代码块、ASCII 排版或 Unicode 伪公式。上面的围栏代码块仅用于展示 Markdown 源码写法，实际解读文档中的独立公式直接使用 `$$...$$`。
- 反引号只用于代码标识符、文件名、命令、配置项和代码片段。若 `value_head` 指代码字段，用反引号；若 $V_\theta(s)$ 指数学对象，用 LaTeX。
- 即使当前查看器不支持数学渲染，也保留 LaTeX 源码，不降级成 ASCII。必要时提醒用户换用支持数学公式的 Markdown 查看器。
- 长公式不要硬塞进行内；改用 `$$...$$` 独立展示，并在相邻段落解释符号和直觉。
- ASCII art 里中英文混排会对齐错位 → 用 Markdown 表格替代。
- Mermaid 在用户环境可能不渲染 → 表格能说清的关系就用表格，否则先问或附源 + 截图说明。

## 9. Scope 守住

- 用户限定了范围就严格守：说「只解读 RL 部分」就只写 RL，不顺带概述全文；说「简短补充」就 1-2 句，不是三段加一个表格。
- Step C6 的 follow-up 尤其注意：想顺带扩展相邻内容的地方，先问用户，不要自作主张展开。

## 10. 人称：无人称写作

解读文档是公开参考材料，不是私人对话。不要出现第一人称（「我认为」「我的判断」「我没看到」）或第二人称（「你问的」「你已知的」「告诉我」）。读者不关心「谁」写了这份解读，第一人称还可能被误读为论文作者发言。

区分「论文事实」和「编辑推断」不靠人称，靠句式：
- ~~「这是我的理解」~~ → 「论文没展开这个机制，可能的原因是…」
- ~~「我没找到」~~ → 「原文未提及」「尚未见到相关实验」
- ~~「你可以选择 X」~~ → 「X 适合 Y 场景」

## 自检节奏

写完一段先停一下问自己：

1. 有几个 `→` `——`？
2. 有「关键 / 本质 / 核心」吗？
3. 有「招 1/2」「列举预告」「来龙去脉」吗？
4. 粗体超过 2 个吗？
5. 有「X 一变，Y 也跟着变」结构吗？
6. 源和我的解读，读者分得清吗？是不是用了括号标签？
7. 有「我」「你」「告诉我」等第一/第二人称吗？
8. 所有数学表达都是 `$...$` 或 `$$...$$` 吗？有没有混入行内代码、代码块或 ASCII 公式？

命中任一就触发改写。
